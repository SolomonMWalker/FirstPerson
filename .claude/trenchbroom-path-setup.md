# TrenchBroom / func_godot Path Setup

This project uses two canonical symlinks so that func_godot's local config points to the same paths on every machine, regardless of where TrenchBroom or the project actually lives.

## Canonical paths (same on every machine)

| Symlink | Points to |
|---|---|
| `C:\TrenchBroomGames` | TrenchBroom's `games/` folder on this machine |
| `C:\TrenchBroomGamePath` | This project's `trenchbroom/` folder on this machine |

The func_godot config (`user://FirstPerson_FuncGodotConfig.json`) then uses:
- `TRENCHBROOM_GAME_CONFIG_FOLDER` = `C:/TrenchBroomGames/GodotFirstPerson`
- `FGD_OUTPUT_FOLDER` = `C:/TrenchBroomGames/GodotFirstPerson`
- `MAP_EDITOR_GAME_PATH` = `C:/TrenchBroomGamePath`

## Setup steps for a new machine

### 1. Create the two symlinks (run PowerShell as Administrator)

```powershell
# Replace these two paths with the actual locations on THIS machine:
$tbGamesFolder   = "E:\GameMakingTools\TrenchBroom-Win64-AMD64-v2025.1-RC2-Release\games"
$projectTBFolder = "E:\Godot\GodotProjects\FirstPerson\trenchbroom"

New-Item -ItemType SymbolicLink -Path "C:\TrenchBroomGames"   -Target $tbGamesFolder
New-Item -ItemType SymbolicLink -Path "C:\TrenchBroomGamePath" -Target $projectTBFolder
```

The canonical destination paths (`C:\TrenchBroomGames`, `C:\TrenchBroomGamePath`) must be identical on every machine. Only the `-Target` values change per machine.

### 2. Write the func_godot config JSON

func_godot stores its local config outside the project at:

```
%APPDATA%\Godot\app_userdata\FirstPerson\FirstPerson_FuncGodotConfig.json
```

Create that file (create the `FirstPerson` directory if it doesn't exist) with this exact content:

```json
{"FGD_OUTPUT_FOLDER":"C:/TrenchBroomGames/GodotFirstPerson","MAP_EDITOR_GAME_PATH":"C:/TrenchBroomGamePath","TRENCHBROOM_GAME_CONFIG_FOLDER":"C:/TrenchBroomGames/GodotFirstPerson"}
```

Or run this PowerShell (no elevation needed):

```powershell
$dir = "$env:APPDATA\Godot\app_userdata\FirstPerson"
if (-not (Test-Path $dir)) { New-Item -ItemType Directory -Path $dir -Force }
Set-Content -Path "$dir\FirstPerson_FuncGodotConfig.json" -Encoding utf8 -Value '{"FGD_OUTPUT_FOLDER":"C:/TrenchBroomGames/GodotFirstPerson","MAP_EDITOR_GAME_PATH":"C:/TrenchBroomGamePath","TRENCHBROOM_GAME_CONFIG_FOLDER":"C:/TrenchBroomGames/GodotFirstPerson"}'
```

### 3. Verify in Godot

Open `addons/func_godot/func_godot_local_config.tres` in the Godot inspector and click **Reload func_godot settings**. The three path fields should show the `C:\TrenchBroom...` paths.

### 4. Set TrenchBroom's game path

In TrenchBroom: **Preferences → GodotFirstPerson** → set the game path to `C:\TrenchBroomGamePath`. This only needs to be done once per machine; it's stored in TrenchBroom's own preferences.

## What lives where (reference)

| Location | What it is | Git-tracked? |
|---|---|---|
| `trenchbroom/` (in project) | Maps, textures, FGD `.tres` files, notes | Yes |
| `C:\TrenchBroomGames\GodotFirstPerson\` | Exported `GameConfig.cfg` + `.fgd` | No — generated by func_godot |
| `%APPDATA%\...\FirstPerson_FuncGodotConfig.json` | func_godot local config (the paths above) | No — machine-local |

## Why the symlinks aren't in git

The symlink targets are absolute paths that differ per machine. The symlinks live on `C:\` (outside the project), and the func_godot config JSON lives in Godot's appdata, so neither belongs in the repo. The docs above are all you need to replicate the setup.
